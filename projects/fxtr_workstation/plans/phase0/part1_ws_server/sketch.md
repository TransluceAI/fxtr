1. implementing the fxtr-facing layer, which holds onto tracked FxtrIDs and services, assigns them short IDs, and allows RPC connections over websocket (but does NOT hold any session state and does not support normal clients), and make sure this works (in particular that you can make two connections to the same server, attach some resources from one, then load them in the other)
2. implementing a basic websocket client connection for a debug UI, but without any sessions; the only thing you can do is list the RPC connections and fetch their registered IDs and service refs. also implement the very basic debug UI at this stage, which for now just shows the RPC connections. have it track and show some useful info about those, in particular: whether the RPC connection is live, what the live registrations are, what service registrations (if any) where originally registered but then deregistered but have not yet drained due to being depended on by some other rpc client, and what service registreations (if any) the rpc client is keeping alive due to having an active `get_service` that has not been released
3. extending out the system to support websocket-driven (non-RPC) client sessions (for the eventual non-rpc agent and UI clients), and implementing all the basic features of the session management _except_ callbacks, then testing that this works according to spec and handles necessary edge cases
4. adding support for client session states and event logs to the debug UI, and testing out that this works in some more complex situations
5. adding callback support: WS can generate its own services for callback creation, then routes calls to this to the connected session. we can integrate this across backend, session interface, debug UI
6 [later moved to 7]. figuring out how to save workstation persistent state; one fairly minimal option would be to have everything in memory by default, but expose a cap for loading and saving entities into an attached store. the most complicated piece here will be to allow loading back from that namespace to be lazy, not copied. probably this could be done by having the workstation server open a namespace, then mint a service mounted in that namespace that can be used to save and load.
