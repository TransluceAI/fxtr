
(rough sketches for possible things in phase 3)
- integrate renderers with draggable panel view system derived from panel spike
    - (prepwork in panel spike) Refactor ViewRegistry to decouple from dockview.
        - ViewRegistry + ViewPortalOwner manages slots, views, and portals, but without dockview-specific logic. Existing concept of a "panel" in the view registry should be mapped to a "RootSlot", keyed by a string key. API for creating root slots, moving things between slots. Handles click, right-click, hover, and drag operations, but does so by redirecting them to some subscribed manager object (defined by an abstract interface). Goal is that the _content_ of a panel should be able to only interface with the ViewRegistry, but ViewRegistry and portal system knows nothing about portals
        - PanelManager: Takes over the panel-specific details from ViewRegistry. Registers itself as the subscribed manager, and handles the location of panels, routing of panel actions to the view manager, and routing of viewregistry callbacks to the appropriate panel action. Responsible for the panel-movement-related items in the right click menu.
    - ViewRegistry and slot/view system: External store managing views, slots, and panels with react-reverse-portal. Refactor existing code to follow panel spike behavior and panel structure, with refs opening new panels or selecting existing ones. Existing details panel refactor to just show a _ref_ to whatever element is being selected in the graph/thinglist, rather than showing its actual contents; all contents show in panel_spike-style normal or preview panels / slots.
        - Embed app should instantiate its own ViewRegistry but with a single root slot that just contains the active thing. Instead of opening refs in a new panel, clicking a ref copies its JSON thing key. Basically an extremely minimal version of the PanelManager with only one panel allowed.
    - Remove old details panel. Instead, any action that currently changes the selected thing should trigger opening a preview panel like we currently do for refs. Also, any action that changes which panel has focus in the dockview should change the selected thing (including opening a preview panel). Now the selected panel is just the one that has focus, and preview panels replace the details panel.
- build out examples to show how to use the library, and integrate better with fxtr (both versions)
